# Техническое задание: Интеллектуальная система базы знаний

## 1. Общие сведения
**Название проекта:** Agent System v2 (AI Docs Assistant)
**Цель:** Создание веб-приложения для автоматизированного поиска ответов по корпоративной документации с использованием искусственного интеллекта (LLM).
**Проблема:** Сотрудники тратят много времени на ручной поиск информации в регламентах и инструкциях.
**Решение:** Чат-бот, который находит релевантные куски текста в базе и формулирует точный ответ на естественном языке.

## 2. Роли пользователей
1.  **Администратор:**
    *   Управляет пользователями.
    *   Загружает и обновляет базу знаний (документы).
2.  **Пользователь (Сотрудник):**
    *   Ведет диалог с системой.
    *   Получает ответы со ссылками на источники (опционально).

## 3. Функциональные требования

### 3.1. Работа с документами (Административная часть)
*   **Загрузка:** Поддержка форматов `.md`, `.txt`, `.pdf` (опционально).
*   **Обработка (ETL):**
    *   Парсинг текста из файлов.
    *   **Чанкинг:** Разбиение текста на смысловые фрагменты (chunks).
    *   **Векторизация:** Преобразование текста в векторы (embeddings) с помощью ML-модели.
*   **Хранение:** Сохранение векторов и метаданных (источник, дата) в векторную базу данных.

### 3.2. Пользовательский интерфейс (Чат)
*   **Авторизация:** Регистрация и вход (JWT токен).
*   **Диалоги:**
    *   Создание нового чата.
    *   Просмотр истории сообщений.
    *   Удаление диалогов.
*   **Генерация ответа:**
    1.  Пользователь отправляет вопрос.
    2.  Система ищет похожие фрагменты в векторной БД (Semantic Search).
    3.  Найденный контекст + вопрос отправляются в LLM (например, GPT/Claude или локальная модель).
    4.  Пользователь получает сгенерированный ответ.

## 4. Технические требования

### 4.1. Стек технологий (Backend)
*   **Язык:** Python 3.9+
*   **База данных:** PostgreSQL 14+ (с расширением `pgvector` для хранения векторов).
*   **Фреймворк:** FastAPI или Flask (исходя из структуры `app/api`).
*   **ORM:** SQLAlchemy (для работы с моделями пользователей и истории).

### 4.2. Архитектура проекта (согласно скриншоту)
Проект строится как монолитное приложение со следующей структурой:
*   `/backend/app/api` — Эндпоинты (ручки) для фронтенда.
*   `/backend/app/services` — Логика (RAG-пайплайн, общение с AI).
*   `/backend/app/models` — Схемы данных Pydantic/SQLAlchemy.
*   `/backend/app/database` — Подключение к БД.

## 5. Этапы работы системы (Data Flow)
1.  **Индексация:** Админ загружает файл -> Система делит его на части -> Создает эмбеддинги -> Кладет в Postgres.
2.  **Поиск:** Юзер пишет "Как оформить отпуск?" -> Система превращает вопрос в вектор -> Ищет ближайшие векторы в БД.
3.  **Генерация:** Система берет найденные инструкции по отпускам и промпт "Ответь на вопрос, используя контекст" -> Отправляет в нейросеть -> Отдает ответ юзеру.

### Рекомендации по реализации (Совет):
Для реализации пунктов из скриншота `README.md` ("разбиение на куски", "векторная БД"), вам понадобятся библиотеки:
*   **LangChain** или **LlamaIndex** (для управления чанками и цепочками диалога).
*   **OpenAI API** (или аналоги) для генерации ответов и эмбеддингов.
*   **FastAPI** для быстрого создания API.
